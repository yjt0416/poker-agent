# 2026-10-01—02 本地全流程验收

## 范围与环境

验收对象为当前根目录代码，不使用旧工作树服务。环境为 Windows、Java 21.0.12.1、Node.js 24.14.1、Chromium 和原生 PostgreSQL 17.11。牌局使用离线 Agent；本轮不调用真实 DeepSeek，也不消耗模型额度。

覆盖大厅选角、玩家行动、聊天、多窗口 SSE、断线补发、刷新恢复、淘汰后观战、完整 AI 锦标赛、冠军与排名、分页回放、战绩、声音设置、移动布局及键盘可达性。暂缓的收藏、成就、主题和完整角色动画不在本次范围。

## 已发现并修复的问题

1. **淘汰后仍可影响牌桌**：聊天入口已隐藏，服务端拒绝已淘汰/完赛玩家的新发言；旧命令回执继续保持幂等。
2. **淘汰后接口残留底牌**：真实浏览器测试发现 BETWEEN_HANDS 投影仍返回上一手自己的底牌。现在淘汰/完赛投影为空；淘汰前的本人历史回放仍可查看自己的底牌。
3. **回放停在首批记录**：播放可自动跨页，也可一次加载全部后续记录。失败后从已加载尾部重试。
4. **回放请求竞态和资源浪费**：StrictMode 的迟到响应不会覆盖新数据；串行分页防止重复加载；离页取消请求；实时事件增加后自动拉取已加载回放的尾部。
5. **回放缺少聊天**：显示该帧的“最近发言”；连续 240 个 ASCII 字符可以换行，不挤出页面。
6. **键盘焦点丢失、结果页死按钮**：回放、战绩、结果页进入时聚焦主标题；清除确认具备警告语义及可恢复焦点；结果页隐藏无效“动态”按钮。
7. **移动操作区可能落到首屏外**：压缩移动牌桌、座位与手牌布局；390×844 下操作区底部不得超过 844px，加入浏览器回归断言。
8. **测试把合法首手结束误判为故障**：若所有 Agent 提前弃牌，玩家用例通过正常下一手入口等待真实行动权。
9. **盲注全下直接结算的终局遗漏**：开始下一手时也记录即时结算的公共牌、本人底牌归档、情绪及结算日志，手数不再多加一。加入确定性恢复回归，真实锦标赛终局回放再次通过。
10. **移动底牌花色被玩家信息遮挡**：调整底牌排布；浏览器通过命中测试确认两个花色实际可见，仍保持操作区在首屏内。桌面侧栏导航也保持单行显示。
11. **淘汰测试提前耗尽命令上限**：合法玩家在第 207 手仍有筹码，400 次命令不足以保证随机比赛结束。提高到 2000，保留四分钟期限和全部权限断言，未完成时输出诊断；三次独立复跑均实际进入淘汰后观战。
12. **Linux CI 暴露异步推进测试竞态**：读到已提交版本不代表 Agent 工作线程已释放占用。连续推进的服务测试仅对精确的忙碌 409 做有期限重试，复用同一命令 ID；其他错误立即失败，生产并发保护保持有效。完整后端套件及三轮专项重复均通过。

## 实测边界

- 本地 `local` profile 是内存存储，进程退出丢失当前牌局。需要重启恢复时必须启用 PostgreSQL；该模式已单独做真实进程重启验证。
- 本轮浏览器为 Chromium，390×844 是模拟视口；没有 Safari/Firefox、真实触屏和屏幕阅读器完整验收，截图尚无像素差异基线。
- 自动 Axe 通过不等于全部人工无障碍标准通过。
- 公网目标主机、域名/HTTPS、生产流量、异地备份与正式故障恢复尚未验收。GitHub CI 的临时 Docker 整栈验证不能代替目标环境验收。
- DeepSeek 真实适配器此前已联调，本轮以离线 Agent 验证完整赛程；尚未用替换后的正式密钥验证整场模型赛程。
- 当前摊牌界面主要显示公共牌和底池结算，尚缺可解释的对手公开牌型展示；规格中的玩家行动倒计时及基础设施失败时的主动恢复提示仍需独立实现/验收。

## 复跑与产物

使用 Java 21 运行 `backend/mvnw.cmd -f backend/pom.xml verify`；前端运行 `npm test`、`npm run build`、`npm audit --audit-level=high`。启动后端后运行 `npm run test:e2e`。完整随机赛程允许最长 12 分钟且不自动重试，CI 游戏任务预留 30 分钟。

本轮分组产物位于被 Git 忽略的 `build/local-acceptance/`：`production-final` 的完整赛程、`production-short-final` 的七项短流程，以及 `production-elimination-final`、`production-elimination-final-2`、`production-elimination-final-3` 的淘汰复跑。用例截图使用 Playwright 各自的输出目录，避免并行补测互相覆盖。
