## 已交付的本轮实现

- REST 负责提交命令，SSE 负责服务端推送。单独的 Web sequence 覆盖行动、聊天和观战推进意图；客户端按序号合并更新，重连补发，超过 200 帧时重置为当前快照。
- 已有牌桌命令包含 tableId、commandId、expectedVersion；服务端持久保存回执，重复请求先检查回执再检查版本。冲突回到最新牌局，不盲目重复下注。
- Agent 推理移到有界后台队列，不再在牌桌锁内等待模型。提交时重新验证版本；观战单步意图可恢复。同步按钮可重新核对队列拥堵或失败后的状态。
- PostgreSQL 中，领域检查点、Web 元数据和脱敏帧在同一外层事务保存。Cookie 摘要对应 8 小时会话。local 模式仍全部在内存中，进程退出不保留。
- 大厅、模式选择、角色选择、继续当前桌、另开桌；锦标赛冠军和全部排名；玩家淘汰后转为观战。
- 基础回放按 100 帧分页，支持逐步、暂停、调速、时间轴和手牌跳转；玩家只见自己底牌，观众不见任何底牌。
- 观战支持 0.5×/1×/2×/4×、连续自动下一手和按角色过滤日志。该速度控制浏览器推进间隔，不能加速 LLM 推理；关闭页面会停止自动观战。
- 修复日志撑高桌面操作区、移动端座位碰撞、加注快捷金额不合法、全下自动发牌后的公共牌遗漏、淘汰后下一手读取未知玩家底牌。
- 删除伪倒计时、伪概率/排名和默认演示桌。断网及时停用操作，恢复后同步；失效 Cookie 自动返回大厅。

## 已知工程边界

- 新建牌桌请求尚未有跨超时幂等键；现有牌桌的行动、聊天、推进和下一手具备幂等回执。
- 开新桌替换当前 Cookie，当前版本无法从前端回看旧桌；已在大厅提前说明。
- 归档目前保存完整脱敏快照，长局会累积存储；需要保留策略和压缩。内存缓存与命令锁也需生命周期管理。
- 单后端实例是当前部署边界；多个实例的本地会话缓存与 Agent 调度尚无协调层。
- 观战任务在队列拥堵/失败时保留推进意图，可通过同步/重连恢复；还需增加明确的任务故障状态和指标。
- 新增数据库集成测试已编译，但不能用内存恢复测试替代真实 PostgreSQL 恢复结果。
